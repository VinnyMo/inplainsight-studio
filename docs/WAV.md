# Experimental WAV carrier (local development)

WAV export and recovery accept originals up to 16 MiB. PNG profiles and limits are unchanged. The planned 1 GB / 4 GB WAV budgets are not implemented capacity.

The carrier is ordinary RIFF/WAVE with a canonical 44-byte header: PCM format 1, mono, 48,000 Hz, signed 16-bit little-endian samples, byte rate 96,000, block alignment 2. There are exactly fmt and data chunks, with no metadata payload or sidecar. Every byte b of the unchanged IPSSTUD1 envelope is represented by sample (b - 128) * 16. Samples range -2048 through 2032. Data length is twice envelope length; total length is 44 + 2E. Payload is in the actual PCM samples.

This is noise audio, attenuated compared with full-scale random PCM; playback equipment or volume normalization can still make it loud. The app never plays it. Do not edit, resample, normalize, convert or record the audio. Recovery supports only the exact canonical carrier, not arbitrary WAV files, RF64, added chunks or audio transmission. There is no error correction.

Framing, Argon2id parameters, secretstream authentication, indexes, lengths and FINAL tags are the existing PNG envelope v1. Both directions of crypto compatibility are tested. A new encryption format is unnecessary at this bounded size. RIFF sizes remain within uint32; envelope maximum is 16 MiB + 16 KiB, making maximum accepted WAV 33,587,244 bytes. All header fields and file length must match before sample decoding. Samples must be canonical; the inner authenticated envelope detects remaining corruption.

The streaming implementation bounds application data reads to roughly 64 KiB and audio conversions to 64 KiB. The 64 MiB KDF, runtime and small codec-independent buffers add memory; this is not a hard process RSS cap. Export creates an encrypted spool, staged WAV and verification spool, decrypts the full staged output, compares plaintext length/SHA-256 with the streamed source and only then publishes using an exclusive same-filesystem hard link. Recovery first spools ciphertext and authenticates it completely without writing plaintext, then asks for a destination, streams a second authenticated pass to a private stage, rechecks length/name/hash, and publishes exclusively. No existing destination is overwritten.

Export scratch is approximately 4E (two ciphertext spools plus 2E audio); recovery is E + original bytes, across temporary/destination volumes. The original source is separate. Free space is not reserved up front; disk errors abort and clean owned stages. Windows temporary access follows inherited filesystem ACLs; chmod is not claimed to establish Unix-style privacy there. Normal cancellation/failure cleans stages; abrupt power loss or process kill can leave stages, including verified plaintext during the recovery write. No crash-recovery sweeper is installed, and storage secure erasure is not claimed.

WAV cancellation is cooperative through a worker shared flag, checked between bounded steps and before publication. Synchronous password derivation cannot be interrupted mid-call. Publication may win a late cancellation race; successful publication is reported as success. PNG retains its existing native Save cancellation and worker behavior. WAV processing phases have a two-minute deadline; native Save-dialog waiting time is excluded by resetting the deadline after the chooser returns. A deadline abort currently uses the same canceled result as user cancellation.

Reference format constraints: Microsoft RIFF overview https://learn.microsoft.com/en-us/windows/win32/xaudio2/resource-interchange-file-format--riff- and PCM packing https://learn.microsoft.com/en-us/windows/win32/multimedia/devices-and-data-types . The narrow parser intentionally accepts fewer variants than ordinary WAV players.
